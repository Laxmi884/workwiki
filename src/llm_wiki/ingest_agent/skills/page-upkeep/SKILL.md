# Keeping pages useful

Pages are read later by the user and by agents answering questions. A page should
answer "what is true now?" at the top and "what happened?" below.

## Current state

Each project (and, when useful, person) page has a "## Current state" at the top: 1-6
lines with what is true now, e.g.

- GA: Dec 9 (moved from Dec 2 after the security review)
- Status: security review passed; two minor fixes before GA
- Owners: Priya (runbook, rollback), Marta (signed URLs)

Rewrite it with `update_summary` when a note changes dates, status, owners or scope.
Read the page first; keep what is still true, replace what changed, and give the full
new state (it replaces the old one). Cite the note lines behind the change.

## Over time

- Facts are appended under their sections; never repeat one that is already there.
- A newer fact can contradict an older one (a date moved again, a plan reversed). File
  the new fact and update Current state; don't edit old entries.
- Prefer existing sections and pages over new ones, unless a rule says otherwise.
